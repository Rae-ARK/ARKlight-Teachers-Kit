# Proposals

Ideas for where Noah could go next that haven't been tried yet —
distinct from `Foundational/`'s settled, permanent record. Mirrors
the purpose of ARKlight's own `docs/Proposals/`, scaled down: no
formal review process is implied here, just "written down before
built" so an idea survives between the occasional sessions this
project gets worked on.

Nothing is filed here yet. Candidates worth writing up once someone
picks one up, straight from `Foundational/SCOPE.md` and
`Foundational/OVERVIEW.md`'s "possible future" notes:

- A second taught concept, once `variables` (the first milestone) is
  working end-to-end.
- Domain components beyond the core loop — `Lesson`, `Question`,
  `CodeExercise`, `Hint`, `ConceptMap`, `Progress` — as they're
  actually needed, not all at once.
- Anything that would change the core teaching loop or student-state
  shape described in `Foundational/TEACHING-MODEL.md` /
  `Foundational/DATA-MODEL.md`.

## Adding a proposal

One file per idea, named for the idea (`SOME-IDEA-PROPOSAL.md`).
State what it's for and why, sketch the shape, and flag open
questions — doesn't need to be exhaustive. Once it's built, fold
anything that's still true into the relevant `Foundational/` doc and
remove the proposal file, the same "graduate or remove" rule
ARKlight's own `Proposals/` folder uses.
